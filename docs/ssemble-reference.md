# Ssemble feature reference for OpenShorts

Public product snapshot reviewed on 25 November 2026, compared with OpenShorts commit `937d75b` on the framing branch. The baseline includes core clipping, stream composition, publishing, and agent workflows. At that revision, the largest gaps concerned repeatable editor controls, channel-specific scheduling, and the campaign marketplace.

**Present** means an implementation path exists in that commit. **Partial** means a related path exists or needs broader coverage. **Gap** means the equivalent product capability was not identified in the reviewed paths. The verification column describes observable behavior for an OpenShorts implementation or provider integration.

The tables below preserve the initial baseline. The later local-work sections record the implementation added through 26 November 2026.

## Quality comparison plan

Use the same source file, time window, output aspect, requested clip duration, language, caption setting, and enabled overlays in both products. Start with owned or licensed footage. Record the source hash, job setting values, OpenShorts revision, provider and model configuration, and the Ssemble account plan and run date. Keep the export and reference labels for each case so a second reviewer can reproduce the score. [Ssemble create options](https://www.ssemble.com/docs/endpoints/create-short) · [OpenShorts API settings](architecture/agent-access.md)

| Fixture | Hold constant | Measure and keep |
| --- | --- | --- |
| Single speaker and an alternating two-person panel | Label speech, active speaker, and both faces on a sample at four frames per second plus every shot boundary. Export matching 9:16 cuts. | Word error rate, median and 95th-percentile caption timestamp error, fraction of samples where the active speaker is clear, and fraction of required two-person shots where both faces remain visible. |
| Slide deck or screen recording | Mark the relevant text area and include off-center and wide charts. Run matched fixed ranges with layout auto and fit where supported. | Percentage of the labelled area kept, small text legibility at equal display size, and cases where captions or hooks cover needed detail. |
| Gameplay with a boxed facecam and a green-screen cutout | Mark the original camera and action windows. Include a camera-only cut and a segment with no webcam. | Duplicate presenter frames, missing presenter frames, gameplay area retained, and count of correct shot-level layout switches. |
| Field sport, combat sport, and fast cutaways | Label the ball, the relevant players or both fighters, and frames where a target is occluded. Score comparable shots or identical manual ranges. | Visible-target coverage on labelled visible frames. Report ball and athlete coverage separately, with stills for crop jitter and wide fallbacks. |
| Two-language source and an edited caption timeline | Use distinct audio tracks with known speech. Include a reordered two-segment edit, Unicode text, a corrected caption, and speech at both cut edges. | Selected audio language, caption accuracy, exact source cut order, number of cues outside the clip, and whether SRT and copied text retain the saved correction. |
| Layered clip with a finished end card | Use the same source interval, B-roll timing, title duration, and end-card length. Fix the soundtrack and start offsets where both editors allow it. | Confirm the bottom-video loop and cue timing, the body and delivery durations, the chime or silence at the card boundary, and one tail after restyling or reopening the clip. |
| Silent footage and a 30–90 minute recording | Hold source duration and number of requested outputs constant where supported. Label silence and several editorial highlights without using either product's ranking. | Count workable clips, compare ranked clips with labelled highlights using timestamp overlap, and report time to first playable clip, time to all clips, and completion or failure. |

1. **Run fixed ranges first.** Export the same intervals to isolate framing, captions, audio sync, and overlays. Check dimensions, 1:1 sample aspect ratio, and duration within one video frame of the requested cut plus any explicit end card. Use matching visual and audio cues near the beginning and end to estimate sync. Flag any caption time outside the clip body or any frame showing both the opening and closing overlays. [OpenShorts output checks](../export_quality.py) · [Ssemble clip options](https://help.ssemble.com/docs/make-clips/custom-options)
2. **Evaluate automatic selection separately.** Have two reviewers mark highlights and rank clips with the product and its score hidden. For each returned clip, compute time intersection divided by time union against the closest labelled highlight. Report precision at the same output count using a 0.5 overlap threshold. Keep the clips reviewers disagreed on with a short explanation. [OpenShorts clip selection](architecture/clip-selection.md) · [Ssemble result fields](https://www.ssemble.com/docs/endpoints/get-shorts)
3. **Exercise normal workflow entry points.** Reopen and edit a saved clip, export from browser and API, review each source-backed change on its current timeline, and test imports with an unavailable track or expiring source. Repeat three runs for latency and failure rates. For a calendar comparison record one scheduled, changed, cancelled, and completed post where an authorized profile supports it. [OpenShorts agent access](architecture/agent-access.md) · [Ssemble post statuses](https://www.ssemble.com/docs/endpoints/list-posts)

Record for every case the fixture, expected outcome, test method, measured outputs, sample size, and a link to evidence. Where a fixture, provider, or feature is unavailable, record that condition alongside the result. This plan requires paired exports before drawing any comparative quality conclusion.

Public Ssemble docs describe product behavior. Its ranking and tracking algorithms, model versions, media rights, provider account configuration, and real-world quality comparisons remain unverified. The automation guide uses a 0–100 score scale. The API result examples also use scores on that scale, while the webhook guide describes a 0–10 scale. Treat these examples as surface-specific until verified against an authorized account.
