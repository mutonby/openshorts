# Ssemble feature reference for OpenShorts

Public product snapshot from 24 November 2026, compared with the existing OpenShorts framing branch at `937d75b`. Local branch references in the matrix describe behavior observed there. The implementation section reflects the upstream port. The core clipping, stream composition, publishing, and agent workflows already have OpenShorts implementations. The largest gaps are in repeatable editor controls, channel-specific scheduling, and the campaign marketplace.

**Present** means an implementation path exists in that commit. **Partial** means a related path exists or needs broader coverage. **Gap** means the equivalent product capability was not identified in the reviewed paths. The verification column describes observable behavior for an OpenShorts implementation or provider integration.

## Verification priorities

1. Build a small corpus with consented footage for a speaker, a panel, a gaming inset, a green-screen cutout, a field sport, a combat sport, and a video with alternate audio. Run it through ingest, clipping, editor, re-render, and export. Score timing, framing, audio sync, transcript fit, and reproducibility. [Upstream export geometry](../reframe_v2.py) · [Rendered layout ranges](../layout_ranges.py)
2. Use the same rendering options for new projects, editor re-renders, CLI or MCP, and automation where they share a feature. Persist the project and clip options in a form that old projects can reopen. [Agent access](architecture/agent-access.md) · [Reframing and sidecars](architecture/layouts-and-reframing.md)
3. Exercise scheduling and rewards with test accounts and permitted assets. Provider approval, account authorization, asset licenses, and payout onboarding are dependencies for production verification. Treat these examples as surface-specific until verified against an authorized account.
